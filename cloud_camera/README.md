# Cloud Camera

Нативное Flutter-приложение камеры для Android и Windows. Пользователь входит в свой
Google-аккаунт, а снятые фото и видео автоматически загружаются в папку
`Cloud Camera` на его Google Drive.

Cloudflare Worker и отдельный сервер не требуются: авторизация и отправка файлов
выполняются напрямую с устройства пользователя.

## Готовые сборки

- `dist/CloudCamera-Android-v1.2.0.apk` — APK для Android.
- `dist/CloudCamera-Windows-v1.2.0.zip` — полный комплект для Windows.

Windows-архив нужно распаковать целиком, затем запустить `CloudCamera.exe`.
Папка `data` и DLL-файлы должны оставаться рядом с EXE.

Текущий APK подписан локальным Android debug-сертификатом. Он подходит для ручной
установки и проверки. Для публикации нужен постоянный release-ключ, SHA-1 которого
также необходимо зарегистрировать в Android OAuth client.

## Интерфейс

- камера занимает главный экран, элементы управления расположены поверх изображения;
- переключение фото/видео, галерея и смена камеры находятся внизу;
- в Windows кнопка выбора камеры скрыта, если камера только одна; при наличии
  нескольких камер открывается список устройств с отметкой активной камеры;
- фонарик показывается на Android только для поддерживаемой задней камеры;
- до входа справа вверху отображается кнопка «Войти»;
- после входа там отображается фото Google-профиля; по нажатию доступны данные
  аккаунта и кнопка выхода;
- техническая очередь пользователю не показывается;
- миниатюра последнего фото открывает единую галерею снимков с устройства и из
  папки приложения на Google Drive;
- фото открываются на весь экран с масштабированием, а готовое фото можно
  добавить из галереи приложения;
- состояние отправки отображается небольшим значком поверх конкретного фото;
- фото можно удалить из приложения; уже загруженное фото перемещается в корзину
  Google Drive, а ожидающее отправки удаляется локально;
- надписи «Фото сохраняются в очередь до подключения» и «Высокое качество» удалены.

Надпись «Высокое качество» была только информационной меткой интерфейса и не
управляла разрешением камеры.

## Как работает загрузка

После съёмки файл ставится во внутреннюю устойчивую очередь и приложение сразу
пытается отправить его в Google Drive. При временном отсутствии сети загрузка
повторяется автоматически. После успешной отправки временная локальная копия
удаляется. Полностью закрытое приложение не может отправлять данные в фоне; очередь
продолжит работу при следующем запуске.

Галерея объединяет локальные ожидающие снимки и файлы, созданные Cloud Camera в
собственной папке Google Drive, без дубликатов. Для просмотра облачного фото нужен
интернет. Удаление облачного фото не уничтожает его безвозвратно: файл остаётся в
корзине Google Drive до её очистки.

Используется scope `https://www.googleapis.com/auth/drive.file`. Приложение получает
доступ только к созданным им файлам и папке, а не ко всему содержимому диска.
Загрузка возобновляемая, частями по 4 МБ, с повторами и защитой от дубликатов.

## Настройка Google OAuth для владельца приложения

В одном проекте Google Cloud должны быть включены Google Drive API и Google Auth
Platform. Нужны три OAuth client:

1. **Android**
   - package name: `com.ailoryink.cloud_camera`;
   - SHA-1 текущей тестовой подписи:
     `7F:8A:59:E0:5C:9B:F7:BC:2F:52:BB:DA:37:85:9A:54:1A:F3:B9:27`.
   - JSON этого клиента в сборку не передаётся: Google сопоставляет приложение по
     package name и SHA-1.
2. **Desktop app**
   - используется Windows-приложением;
   - вход открывается в системном браузере и возвращается через временный локальный
     адрес `localhost`;
   - JSON этого клиента передаётся скрипту сборки.
3. **Web application**
   - его Client ID используется Android-плагином как server client ID;
   - Client Secret этого Web client в APK не помещается;
   - redirect URI и Cloudflare Worker для него не нужны.

OAuth JSON-файлы нужно хранить вне репозитория. Они исключены правилами
`.gitignore`. Пользователь приложения этих данных не видит и ничего вручную не
вводит.

В **Google Auth Platform → Data Access → Add or remove scopes** добавьте
`openid`, `userinfo.profile`, `userinfo.email` и
`https://www.googleapis.com/auth/drive.file`, затем нажмите **Update** и **Save**.
Полный scope `/auth/drive` добавлять не нужно. Пока приложение находится в статусе
Testing, аккаунты пользователей должны быть добавлены в Test users. Для
распространения среди клиентов переведите приложение в Production и выполните
требования Google, показанные в консоли.

Если Google показывает `Ошибка 403: access_denied` и сообщает, что приложение
тестируется, откройте **Google Auth Platform → Audience → Test users**, нажмите
**Add users** и добавьте точный Google-адрес, используемый для входа. После
сохранения пересборка приложения не требуется.

Если загрузка возвращает `insufficient_scope`, значит существующий токен был
выдан без `drive.file`. После добавления scope в Data Access выйдите из Google в
Cloud Camera и войдите снова, подтвердив доступ к Drive. Локальные файлы при
выходе не удаляются и будут отправлены после повторного входа.

## Проверка и сборка

```powershell
flutter analyze
flutter test
```

Для release-сборки используйте скрипт, который читает OAuth JSON снаружи проекта и
передаёт нужные значения через `--dart-define`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tool\build_release.ps1 `
  -DesktopCredentialsPath "C:\path\desktop-client.json" `
  -AndroidServerCredentialsPath "C:\path\web-client.json" `
  -Target All `
  -FlutterPath "C:\path\flutter\bin\flutter.bat"
```

Результаты Flutter:

- Android: `build/app/outputs/flutter-apk/app-release.apk`;
- Windows: `build/windows/x64/runner/Release/`.

## Ограничения

- Windows-сборка пока не подписана коммерческим сертификатом, поэтому SmartScreen
  может показать предупреждение.
- Возможности фонарика и ручных настроек зависят от камеры и платформенного плагина.
- Живой вход Google требует доступной сети, включённого Drive API и корректного
  статуса OAuth consent screen.
